# 架构设计文档 (Architecture Design)

## 1. 系统概述

### 1.1 设计哲学

诸葛亮框架遵循以下核心设计原则：

1. **动态优于静态**：拒绝固定模板，采用实时生成
2. **组合优于继承**：通过组合多个专业 Agent 解决复杂问题
3. **透明优于黑盒**：所有角色定义和决策过程对用户可见
4. **可逆优于不可逆**：支持角色创建、修改、销毁的完整生命周期

## 2. 核心模块详解

### 2.1 任务理解模块 (Task Comprehension Module)

**职责**：深度解析用户指令，识别关键要素

**输入**：用户原始指令（文本）

**输出**：结构化的任务描述对象

```typescript
interface TaskDescription {
  goal: string;           // 核心目标
  domain: string[];       // 涉及领域
  complexity: 'low' | 'medium' | 'high';
  constraints: string[];  // 约束条件
  expectedOutput: string; // 期望输出格式
  deadline?: string;      // 截止时间（如果有）
}
```

**处理流程**：
1. 提取关键词和意图
2. 识别领域标签（法律、技术、创意等）
3. 评估任务复杂度（基于 token 数、领域交叉度）
4. 识别显式和隐式约束

---

### 2.2 角色生成引擎 (Role Generation Engine)

**职责**：根据任务描述动态生成角色定义

**核心算法**：

```
输入：TaskDescription
输出：RoleDefinition[]

1. 任务拆解
   └─ 将大任务分解为 N 个子任务

2. 角色映射
   └─ 对每个子任务 T_i：
       a. 识别所需技能集合 S_i
       b. 确定工作类型（分析/创造/执行/沟通）
       c. 生成角色画像：
          - 角色名称（描述性命名）
          - 专业领域
          - 核心技能
          - 性格特征
          - System Prompt

3. 角色优化
   └─ 合并相似角色
   └─ 检查角色覆盖度
   └─ 输出最终角色列表
```

**角色生成 Prompt 示例**：

```markdown
你是一位角色设计专家。根据以下任务需求，生成一个专业角色定义：

任务描述：{task_description}
所需技能：{required_skills}
工作类型：{work_type}

请生成：
1. 角色名称（简洁专业，如"资深数据分析师"）
2. 角色背景（100 字内）
3. 核心能力（3-5 条）
4. 性格特征（3 个关键词）
5. System Prompt（200 字内，包含行为准则和输出格式）
```

---

### 2.3 协调与监控器 (Coordinator & Monitor)

**职责**：管理多 Agent 协作流程

**核心功能**：

| 功能 | 描述 | 实现方式 |
|------|------|---------|
| **任务分发** | 将子任务分配给对应 Agent | CoPaw `multi_agent_collaboration` skill |
| **进度轮询** | 定期检查各 Agent 状态 | Heartbeat 机制 + Cron 定时任务 |
| **冲突解决** | 处理 Agent 间的输出冲突 | 投票机制 / 专家裁决 / 用户介入 |
| **结果聚合** | 汇总所有子任务输出 | 结构化合并 + 逻辑校验 |
| **异常处理** | 处理超时、错误等异常 | 重试机制 / 角色替换 / 降级方案 |

**状态机设计**：

```
[等待] → [进行中] → [完成]
    ↓         ↓
    │     [阻塞] → [恢复] → [进行中]
    │         ↓
    └──→ [失败] → [重试]
```

## 3. 数据流设计

### 3.1 单次任务流程

```
用户指令
  ↓
[诸葛亮] 任务理解模块
  ↓
TaskDescription 对象
  ↓
[角色生成引擎] → 生成 RoleDefinition[]
  ↓
[Agent 工厂] → 实例化 Agent[]
  ↓
[任务分发] → 分配子任务
  ↓
[监控器] → 轮询状态
  ↓
[结果收集] → 收集输出
  ↓
[聚合器] → 生成最终报告
  ↓
用户
```

## 4. 持久化策略

### 4.1 临时角色 vs 持久角色

| 类型 | 存储位置 | 生命周期 | 示例 |
|------|---------|---------|------|
| **临时角色** | 内存中 | 任务结束即销毁 | "火星法律专家" |
| **持久角色** | `~/.copaw/workspaces/default/agents/experts/` | 永久保存，可复用 | "Python 爬虫专家" |

### 4.2 记忆管理

- **短期记忆**：当前任务上下文，存储在会话变量中
- **长期记忆**：角色定义、任务历史、经验教训，存储在 `MEMORY.md` 或专用数据库
- **记忆压缩**：定期将关键信息摘要写入长期记忆，避免上下文爆炸

## 6. 性能优化

### 6.1 Token 优化

- 角色定义精简：控制在 500 tokens 内
- 上下文窗口动态分配：简单任务用小窗口，复杂任务用大窗口
- 历史对话压缩：使用摘要替代原文

### 6.2 并发控制

- 最大并发 Agent 数：默认 10 个（可配置）
- 批量任务分组：避免同时创建过多 Agent
- 限流机制：防止 LLM API 超限

---

## 7. 安全与隐私

- **数据隔离**：不同任务间的数据严格隔离
- **权限控制**：敏感操作（如删除 Agent）需用户确认
- **审计日志**：记录所有角色创建和任务分配操作
